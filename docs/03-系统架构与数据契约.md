# 系统架构与数据契约

## 架构决定

ResearchPath 采用本地优先模块化单体：

```text
React/Vite
    │ HTTP + JSON
FastAPI（路由、契约、任务、持久化）
    │ JSON request/result
Rscript（统计估计）
    │
本地 SQLite、数据文件、结果与导出
```

服务默认只监听 `127.0.0.1`。项目不包含账号、云同步或遥测。原 ADR-001 与后续审计快照已归入 `archive/project-history/`；本文件是当前架构说明。

## 活动目录

| 路径 | 职责 |

| `apps/web/src/` | React 界面、领域 API 客户端、类型和结果呈现 |
| `apps/api/app/api/` | HTTP DTO、依赖和路由翻译 |
| `apps/api/app/services/` | 领域编排、任务、存储、导出 |

机器入口与活动切片以 `project.manifest.json` 为准。

## 分层约束

- services 和 engine 不得导入 `app.api` 或 `app.main`。
- route 负责 HTTP 错误映射；统计选择留在 service/R。
- `apps/web/src/api/index.ts` 和 `apps/web/src/types.ts` 仅是兼容 barrel。
- 新领域代码写入聚焦模块，不继续扩张兼容 barrel。
- 文件或数据库副作用前校验持久化路径、对象身份和资源预算。
- 任务停止、数据清理和恢复只能作用于用户指定对象。

## 契约同步

JSON Schema、Python contract、OpenAPI 和 TypeScript 类型必须共同变化。主契约位于：

- `specs/dataset-version.schema.json`
- `specs/measurement-version.schema.json`
- `specs/model-spec.schema.json`
- `specs/result-bundle.schema.json`
- `specs/advanced-analysis-spec.schema.json`
- `specs/advanced-result-bundle.schema.json`
- `specs/study-context.schema.json`
- `specs/empirical-result-bundle.schema.json`（实证报告 report.json 顶层门控，入库前校验）

生成与检查使用 `scripts/generate-contracts.ps1`。不得直接修改生成的 TypeScript/OpenAPI 结果而不修改源契约。

### 非有限数与缺失值

R 输出层与 Python 入库归一化层都必须阻止 NaN/Inf/-Inf 进入标准 JSON。转换为 `null` 时，结果在 `provenance.nonFiniteValues[]` 记录 RFC 6901 JSON Pointer `path` 和 `originalKind`（`NaN`、`Inf`、`-Inf`），并生成 `NON_FINITE_RESULT_VALUE` 顶层警告。普通 R `NA` 仍作为常规缺失值序列化为 `null`，不得误报为计算异常。递归清洗必须保留命名 `NULL` 元素及兄弟字段顺序，不能因 R 的 `[[<- NULL` 删除语义破坏结果对象。

## 任务进度事件（SSE）

`GET /api/v1/analyses/{run_id}/progress` 是公开的 SSE 流（EventSource 无法携带自定义头），因此事件只投影白名单字段：

- `id`、`status`、`stage`、`progress`、`completedReplicates`、`totalReplicates`、`errorCode`；
- `metadata.contextHash`（前端旧结果一致性提示需要）。

`error` 原文、`options`、`contextLineage`、`resultPath` 等不出接口，错误文案经 `GET /analyses/{run_id}` 读取。监听器有界：每 run ≤2、全局 ≤50，超限时 SSE 立即结束，前端回退到轮询（`useJobProgress`：SSE 断连后 2s 轮询 + 指数退避重连）。

## 核心身份

- DatasetVersion：不可变数据版本与来源。
- StudyContextRecord：项目级时间结构、依赖结构与研究设计修订。
- DatasetStructureRecord：数据版本上的 subject、cluster 与 time 角色修订。
- MeasurementVersion：构念、题项方向和计分规则。
- ModelSpec / AdvancedAnalysisSpec：模型、变量角色、参数、种子和方法。
- ResultBundle / AdvancedResultBundle：估计、诊断、警告、方法执行和出处。
- Job：排队、运行、完成、失败、取消等生命周期。
- ProcessCatalogMatch：结构状态、目录版本、匹配类型、模型编号、显示名、可执行性和不支持原因。

对象 ID、工作区路径和结果路径必须绑定校验，不能只验证“路径存在”。

## PROCESS 识别与执行门禁

PROCESS 模型采用三层职责：

1. `semantics.py` 检查节点、路径、角色和调节目标等结构语义；
2. `process_catalog.py` 将合法拓扑归一化，并与版本 `5.0` 的 55 个当前编号匹配；
3. `analysis_jobs.py` 在创建估计任务前再次检查冻结验证结果的 `executionAvailable`。

`ModelValidationResponse` 的跨语言字段为：

- `structuralStatus`、`errors`、`warnings`；
- `catalogVersion`、`matchStatus`、`processModelNumber`、`displayName`；
- `executionAvailable`、`unsupportedReason`、`sampleFlow`。

`matchStatus=exact` 只表示命中目录，不能替代执行许可；`custom` 表示结构合法但未命中编号；`invalid` 表示结构本身不能冻结为可解释模型。前端消费服务端响应，不维护第二套“猜测是否可运行”的目录。JSON Schema、Python response、OpenAPI 与 TypeScript 类型必须同步变化。

## 高级能力发现

`GET /api/v1/advanced/capabilities` 返回后端注册表。family 有 runner 不代表所有组合可执行；具体 spec 仍需匹配 `slice_for_spec`，并满足切片的 `executionAvailable` 与支持边界。无法匹配的请求应返回结构化 501，而不是静默降级。

能力发现与验证响应必须同时携带 `executionAvailable`、`validationLevel`、`validationEvidence`、`maturityLevel`、`publicationEligibility` 和 `publicationEligibilityReason`。前者仅回答当前 runner 能否执行；validation evidence gate 派生验证层级与成熟度；论文资格则明确其能否承担论文主分析。`internally_validated` 对应 `validated/conditional`，`externally_validated` 对应 `reviewer_ready/conditional`；只有后续 publication gate 才能派生 `publication_ready/eligible`，不得由 slice ID allowlist 或任务运行成功直接升级。研究设计的内部枚举可保留 `quasi_experimental` 以读取既有数据，但公开文案称为“非随机比较”，且它不能匹配随机实验切片或宣称 DiD、IV、RDD、IPW 等因果识别。

结果证据的 `currentEvidence=true` 还要求当前 repository 中的 StudyPlan、Dataset、Sample 和 Measurement 身份同时匹配；Sample/Measurement 的版本 ID 与 hash 任一变化、缺失或无法解析时，结果必须标记 `stale`、阻断 publication eligibility，并将固定 reason code 传播到 provenance 与 Evidence Graph，不能只依赖 Dataset hash。

`causalTarget` 是合法的 StudyPlan 草稿值，但冻结还必须通过显式 capability 的因果识别元数据；当前 active capability 均不支持 causal target，因此 `causalTarget=true` 的计划必须以 `STUDY_PLAN_CAUSAL_TARGET_UNSUPPORTED` fail closed，不能因 randomized 设计、PROCESS/SEM 间接效应或执行成功而自动获得因果资格。
