# 资产包与历史档案

## 为什么归档

活动文档只描述当前产品。历史实现记录、旧规划、审计快照和未启用代码若与当前说明混排，会造成“曾经计划/存在文件”等于“当前可用”的误判。因此本轮将 31 份阶段文档合并为 9 份主题文档，并把需要保留的原始证据归位到 `archive/`。原来已纳入版本控制的旧 Markdown 可从 Git 历史恢复；未跟踪的近期整改/恢复记录已把有效结论吸收到当前文档，不再保留重复原稿。

## 恢复资产的步骤

1. 用当前代码确认缺口，不能只读资产 README。
2. 选择最小能力切片和明确支持边界。
3. 将需要的实现迁入活动目录，不从 archive 直接 import。
4. 适配当前 schema、对象身份、任务、错误和导出契约。
5. 添加 R/Python/Web/E2E 分层验证。
6. 运行专项、Quick 和 Full。
7. 更新 manifest、能力矩阵和资产 README。

## 保存与清理原则

- 原始安全 finding、复验报告和关键恢复材料保留。
- 可由 Git 完整恢复、且没有独立证据价值的重复阶段周报不保留副本。
- 临时输出、缓存、运行日志和可再生成产物不进入 archive。
- archive 默认不参与 import、route、coverage、build 或 release。
- 归档脚本可能依赖旧路径；未适配前不得直接执行。
