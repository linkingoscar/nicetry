# ADR-001：本地优先架构

- 状态：已批准
- 日期：2026-07-13
- 决策人：项目所有者

## 背景

产品只供个人使用，处理可能含敏感信息的问卷数据。目标是提供网页式交互，同时使用 R 的成熟统计生态。项目不需要账号、多人协作、云部署或商业许可能力。

## 决定

采用以下架构：

- 浏览器中的 React/TypeScript 前端；
- 只监听 `127.0.0.1` 的 Python/FastAPI 本地服务；
- 由 Python 以受控子进程调用 Rscript；
- SQLite 保存元数据，原始文件和 Parquet 保存在项目目录；
- ModelSpec/ResultBundle JSON 是各层唯一交换协议；
- MVP 使用 PowerShell 启动器，不立即封装桌面壳；
- 无账号、无遥测、默认无外部网络请求。

## 原因

- 保持数据和计算在本机；
- 浏览器 UI 适合画布、表格和图形交互；
- Python 适合文件格式、API 和任务管理；
- R 适合统计验证并为 lavaan 扩展保留路径；
- 单体本地架构降低单人项目运维成本；
- 明确协议可以将 UI 与计算解耦并支持复现。

## 被否决方案

### 纯 Python 统计栈

优点是语言统一，但会增加后续 SEM 能力和与 R 研究生态对照的成本，因此不采用。

### 纯 R/Shiny

能快速完成统计原型，但复杂节点画布、前端状态和长期产品化灵活性不足，因此不作为正式架构。

### Electron/Tauri 首发

能提供桌面体验，但会过早引入打包、更新和 sidecar 管理。核心闭环稳定后再评估。

### 云端 SaaS

与个人本地使用目标不符，会新增隐私、账号、部署和维护负担，因此排除。

## 后果

正面：数据不出机器、统计与界面职责清晰、可以分别测试和升级。

负面：需要维护 TypeScript、Python、R 三套环境；Windows 安装和进程管理需要专项测试；网页应用仍需防止本机恶意页面调用 localhost API。

## 约束

- 统计结果不能由前端计算。
- API 不得监听所有网卡。
- R 调用不得拼接用户可控命令文本。
- 三套依赖必须锁定版本。
- 统计协议变更必须有迁移和金标准测试。

## 复审条件

以下任一情况发生时复审：

- 需要跨平台分发；
- 需要多人协作或云同步；
- 本地环境安装成为主要使用障碍；
- 统计任务需要并发或超出单机资源；
- Tauri/桌面封装能显著降低安装成本且不破坏 R 引擎。
