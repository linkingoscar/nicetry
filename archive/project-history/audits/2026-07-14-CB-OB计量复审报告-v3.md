## 一、结论摘要

当前版本的统计能力广度确有明显提升：后端已经覆盖 Model 1/4/6/7/8/14/15、OLS/HC3、BC bootstrap、观测变量 Logistic、lavaan SEM/WLSMV、多组等值性、EFA/CFA、信效度、分层回归和常用组间比较。版本化、数据哈希、固定随机种子、后台取消和复现包仍是产品的突出优势。

但是，第二次审查给出的 **91/93/72** 已不适合作为当前版本的质量结论。此次复审发现多个会阻断使用或改变论文结论的问题：

1. 前端当前不能通过 TypeScript 编译，也不能生产构建，普通用户无法完成端到端操作。
2. Promax 选择会稳定触发后端 500，而不是返回斜交旋转结果。
3. SEM 虽允许选择 FIML，但进入 lavaan 前已经删除全部非完整案例，实际仍是 listwise deletion。
4. 二分类模型存在 Logistic 失败后静默回退 OLS、HC3 被忽略、简单斜率误用 t 分布等问题。
5. 自动学术解读把简单斜率误写成条件间接效应，并在问卷全实证报告中默认套用 Model 4 叙事，存在直接误导论文写作的风险。
6. 简单斜率图使用了后端并未返回的字段，截距和 W 主效应会被置为 0；横轴也不是承诺的 X 均值 ±1 SD。
7. 新增的 CFA-lavaan 交叉验证测试本身尚不能验证目标：运行中异常退出，且数据结构映射与当前 CFA 输出不一致；独立抽查也显示多项指标未达到计划的 `1e-5` 容差。

因此，当前版本可以视为“**统计研发预览版**”，不能视为“可直接支持各类 CB/OB 论文的一站式稳定工具”。

### 3.2 CFA 与 lavaan 数值抽查

使用 lavaan 0.6-21 的 `HolzingerSwineford1939` 三因子模型复算。标准化载荷非常接近，但拟合指标未达到实施计划承诺的绝对误差 `≤ 1e-5`。

| 指标 | 研径手写 CFA | lavaan ML | 绝对差异 |
|---|---:|---:|---:|
| χ² | 85.022086 | 85.305522 | 0.283436 |
| CFI | 0.930641 | 0.930560 | 0.000081 |
| TLI | 0.895961 | 0.895839 | 0.000122 |
| RMSEA | 0.092061 | 0.092121 | 0.000060 |
| RMSEA 90% CI 下限 | 0.071315 | 0.071418 | 0.000103 |
| RMSEA 90% CI 上限 | 0.113661 | 0.113678 | 0.000017 |
| SRMR | 0.06520509 | 0.06520506 | < 0.000001 |

主要原因是手写 CFA 使用 `(N-1) × FML`，而 lavaan 默认 ML 的标度与此不同。载荷结果说明优化器基本正确，但不能再声称“与 lavaan 全指标严格一致”。应明确选择 lavaan 的 normal 或 wishart 口径，并让实现、测试和文档使用同一口径。

## 四、关键问题

### P0：发布阻断与高误导风险

#### 1. 前端不能编译和构建

- 证据：`apps/web/src/components/ResultPanel.tsx:375`、`:382`、`:468`。
- 影响：当前用户不能从源码得到可运行网页；SEM 渲染、等值性表和简单斜率图均无法实际验收。
- 建议：先修复 JSX 文本转义，再把 `test:web`、`typecheck:web`、`build:web` 设为合并前强制门禁。

#### 2. Promax 斜交旋转会使整个实证分析请求失败

- 证据：`engine/R/run_empirical_analysis.R:252-280` 把 `factanal` 的题项相关矩阵误当成因子相关矩阵，随后执行 `loading_matrix %*% factor_correlations`，维度不匹配。
- 实测：选择 `rotation=promax` 返回 HTTP 500，R 错误为 `non-conformable arguments`。
- 影响：旧报告中“Promax + 结构矩阵已正确实现”的判断不成立。
- 建议：从旋转变换矩阵正确恢复 Φ；共同度使用 `diag(Λ Φ Λ')`，结构矩阵使用 `Λ Φ`。在修复前应从 UI 隐藏 Promax，而不是静默提供不可用选项。

#### 3. SEM 的 FIML 是名义支持，实际执行完整案例删除

- 证据：`engine/R/run_analysis.R:64-66` 在设置 `missing='fiml'` 前已经执行 `complete.cases()`。
- 影响：缺失非完全随机时，样本量、路径系数、标准误和拟合指标都可能偏移；结果的 `missingMethod` 仍会写成 FIML，形成错误方法声明。
- 建议：ML+FIML 路径不得预删含缺失观测，只应删除完全无信息或缺少必要分组字段的记录；同时报告每变量缺失、pattern、有效 N 和 lavaan 实际 missing 参数。修复前禁用 FIML 选项。

#### 4. 自动学术解读存在语义错配

- 证据：
  - `apps/api/app/services/academic_interpreter.py:238-245` 把 `result.probes`（简单斜率）称为“条件间接效应”。
  - `:35-36` 在没有 `run.template` 的问卷全实证报告中默认 `model_4`，因此一般描述/EFA/CFA 报告也会生成中介模型叙事。
  - `:189` 固定写“5000 次 Bootstrap”，不读取实际重复次数。
  - SEM 路径存放于 `semResult.paths`，但 `:70` 和 `:146` 读取空的 `result.effects`。
- 影响：用户可能把错误文字直接粘贴到论文，风险高于单纯缺少解释。
- 建议：在契约级测试完成前暂时关闭“自动学术解读/APA 报告”；之后按明确的结果类型做穷举式渲染，所有数字与方法参数必须从 ResultBundle 读取，不能硬编码。

#### 5. 简单斜率图会画出错误的纵向位置和横轴尺度

- 证据：`apps/web/src/components/ResultPanel.tsx:26-39` 查找后端不存在的 `predictorNodeId`；后端系数只有 `term`。找不到时 `b0=b2=0`。` :46-47` 又固定使用 X=-1/+1，而不是 X 的均值 ±1 SD。
- 影响：图形看似合理但不是对应模型的预测值；多条调节路径时还无法区分目标方程/目标边。
- 建议：后端直接返回 plot-ready 数据：`targetEdgeId`、`equationId`、X 原始/中心化取值、W 取值、预测 Y、CI。前端只画返回点，不再逆向重建方程。

### P1：会影响计算或论文方法声明

#### 6. Logistic 支持范围被高估，且存在静默改模型

- `engine/R/run_analysis.R:408-425` 只识别数值 0/1；1/2 或字符二分类不能可靠进入 Logistic。
- GLM 拟合异常时，`:424-425` 静默退回 `lm()`，没有阻断或警告。
- `:433-446` 在 GLM 下即使用户选 HC3 也返回普通 `vcov()`，但 provenance 仍可能写 HC3。
- `:707-728` Logistic 简单斜率仍使用 t 分布和 t 临界值，应使用 z/正态近似或专门方法。
- `:879`、`:905` 二分类 Y 的总效应固定用 `lm()`，与 Y 方程的 logit 尺度不一致。
- 影响：二分类购买/离职/选择结果不能笼统宣称“已支持 PROCESS Logistic”。
- 建议：首先只开放“0/1 二分类 Y 的单方程 Logistic”；拟合失败必须失败并解释。若保留二分类中介/调节中介，要明确效应尺度、总/直接/间接效应定义，并用已验证的参考实现交叉测试。

#### 7. WLSMV 等值性约束不完整

- 证据：`engine/R/run_analysis.R:163-166` 对所有估计器使用 loadings → intercepts → residuals；有序指标的 scalar invariance 应重点约束 thresholds，而不是照搬连续变量截距流程。
- 等值性子模型没有复用主模型的 `missing`、`se` 和 bootstrap/robust 配置，主模型与比较模型口径不完全一致。
- 建议：连续 ML 与有序 WLSMV 分开编译等值性层级；报告每组 N、收敛、Heywood/非正定警告和 robust/scaled Δ 检验。

#### 8. CFA 交叉验证尚未完成

- 自动测试在第二次 lavaan 调用时以 Windows 进程异常码退出。
- 即使进程不退出，测试代码期望 `cfa.fitIndices` 和对象化 `cfa.loadings`，而当前问卷 CFA 输出是顶层拟合指标与 `standardizedLoadings` 数组，测试映射仍需重写。
- 独立数值抽查显示计划中的 `1e-5` 口径不能通过。
- `engine/R/run_empirical_analysis.R:354` 在 CFI 分母不可用时仍返回 1.0，和旧报告所称“不可用不再返回完美值”不一致。
- 建议：确定 ML 标度后，至少使用 3–5 个公开数据集覆盖良好拟合、差拟合、近奇异、两指标因子和缺失数据。

#### 9. 区分效度可能在证据缺失时被判定通过

- 证据：`engine/R/run_empirical_analysis.R:428-430` 使用 `all(..., na.rm=TRUE)`；当比较值全部为 NA 时，结果可能为 TRUE。
- CFA 不可用时，CR/AVE 会用单因子特征分解载荷回退计算，容易让探索性替代值看起来像确认性证据。
- `r_sem_helpers.R:123` 对负载荷取绝对值会掩盖反向计分或模型设定错误；负载荷应先触发诊断，而不是直接转正。
- 建议：效度结论改为 `pass/fail/not_evaluable` 三态；确认性 CR/AVE 只使用收敛且可接受的 CFA/SEM；Fornell–Larcker 优先使用潜变量相关 Φ，并显式显示证据来源。

#### 10. 平行分析不可复现

- 证据：`engine/R/run_empirical_analysis.R:199-215` 使用随机模拟但没有设置或记录 seed，仅 100 次迭代。
- 独立重复调用得到不同阈值，最大差异示例约 0.05045。
- 建议：把 seed、迭代数和分位点放入配置与 provenance；发布默认至少 1000 次，测试用较少次数可以单独配置。

#### 11. 组间比较和实验设计覆盖不足

- 两组使用 Welch t，但效应量仍是 pooled-SD Cohen d；小样本建议 Hedges g，并明确方差假设。
- 多组仅有经典 one-way ANOVA + Tukey/Bonferroni，没有 Levene/Brown–Forsythe、Welch ANOVA、Games–Howell。
- 不支持 2×2/多因素 ANOVA、ANCOVA、重复测量/混合设计、计划对比和操纵检验工作流。
- 影响：大量典型 CB 实验论文不能一站式完成。

#### 12. “完整 SEM”目前主要是 API 能力，不是完整前端能力

- ModelBuilder 可以切换 `family='sem'` 和选择 ML/WLSMV，但没有创建潜变量、绑定指标、设置残差相关或结构路径约束的 UI。
- 因而普通用户很难从现有界面构造测试中使用的 `latents` 规格。
- 建议：要么明确标注“观测变量路径 SEM/API 预览”，要么增加潜变量/指标编辑器和预运行识别检查。

### P2：完整性、可复现和体验改进

#### 13. Excel 导出没有覆盖界面已计算的关键证据

当前 `export_empirical_workbook()` 未完整导出相关 p/N 矩阵、Harman/KMO/Bartlett、CFA 拟合与载荷、Fornell–Larcker、HTMT 及 CI、事后比较明细、ΔR²/F-change、标准化 β、f²。用户仍需手工抄表。

#### 14. 新方法选项没有严格契约校验

`correlation_method`、`rotation`、`factor_count_method` 在 Pydantic 中是任意字符串；无效值会在 R 端悄悄回落到默认方法。应使用 `Literal`/枚举并返回 422。

#### 15. 状态持久化只完成了一部分

`App.tsx` 保存的是当前视图和 dataset/measurement 对象，不保存或恢复 ModelBuilder 的实际画布草稿。刷新后仍会重新创建 Model 4 模板；后端虽自动保存草稿，前端没有加载草稿的闭环。

#### 16. 文档与实现漂移

README 仍把系统描述为 Model 1/4/7/14，未准确说明 Model 6/8/15、SEM、BC、Logistic 的支持边界，也未披露当前限制。测试文件对新增前端参数的断言也没有同步更新。

## 五、CB/OB 论文场景模拟

## 七、建议的修复路线

### 阶段 A：先恢复可信运行（P0）

1. 修复前端 JSX、过期测试和类型枚举，确保四个门禁全部通过。
2. 暂时隐藏 Promax、FIML、自动解读、简单斜率图和高级 Logistic 组合，直到各自验证完成。
3. 删除 Logistic→OLS 的静默 fallback；任何估计器切换必须由用户明确选择并写入 provenance。
4. 给所有方法选项增加 API 枚举和非法输入测试。

验收标准：全套测试 100% 通过；生产构建成功；任一失败方法返回可操作错误，绝不悄悄换方法。

### 阶段 B：修复计量核心（P1）

1. 真正实现 ML-FIML，并用带 MCAR/MAR 缺失的合成数据与 lavaan 对照样本量、参数和 SE。
2. 重做 Promax 的 Φ、共同度和结构矩阵；用 `psych::fa` 或已知矩阵交叉验证。
3. 分开实现连续 ML 与有序 WLSMV 的等值性约束，加入 thresholds 和 robust/scaled 比较。
4. 统一手写 CFA 与 lavaan 的 likelihood 标度；重写交叉验证映射并覆盖多数据集。
5. 将效度结论改为三态，负载荷/Heywood/非正定/不收敛必须显式警告。
6. 明确 Logistic 的允许范围和效应尺度，再补 z、稳健协方差、OR/CI、校准与分类诊断。

验收标准：每个公开选项都有至少一个独立金标准数值测试、一个失败边界测试和一个 API 契约测试。

### 阶段 C：补全论文交付体验（P1/P2）

1. 后端生成图形数据，前端不重算统计量；路径图、简单斜率图支持 SVG/PNG 导出。
2. Excel/Word/LaTeX 导出覆盖所有实际呈现表，并带 N、缺失策略、估计器、SE、seed、重复次数和方法脚注。
3. 自动解释改成规则化、类型安全的陈述生成器；禁止自动写“假设得到支持”，只报告统计证据与必要限制。
4. 从后端恢复真实模型草稿，增加撤销/重做、离开页面提示和更低频的自适应任务轮询。

### 阶段 D：按论文类型扩展，而不是继续堆 PROCESS 编号（P2）

优先顺序建议：

1. CB 实验：多因素 ANOVA/ANCOVA、planned contrasts、重复测量、稳健事后比较。
2. OB 嵌套数据：cluster-robust SE、ICC、两层回归与多层中介。
3. 缺失和稳健性：多重插补、敏感性分析、异常值稳健结果并列报告。
4. 纵向：纵向等值性、交叉滞后/RI-CLPM、增长模型。
5. 功效与稳健性：模拟功效、最小可检测效应、规格曲线/稳健性表。

## 八、可保留的优点

- 数据本地化、原始数据只读、模型/测量版本冻结和哈希追踪的架构方向正确。
- 连续变量 OLS 与 HC3 的核心系数和协方差已有 NumPy 独立对照。
- Model 6 的三条特定间接路径、Model 8/15 的条件间接效应主体公式正确。
- BC bootstrap 实现的是合理的 bias-corrected 区间；应明确它不是 BCa。
- 标准化 β 公式正确；`t²/df_error` 可作为单参数的局部/partial f²，但输出标签应写清定义。
- Nagelkerke R² 实现正确。
- 固定 seed 的 PROCESS bootstrap、后台进度/取消和复现 ZIP 设计值得继续保留。

## 九、最终发布建议

在以下条件满足前，不建议把当前版本用于正式论文的最终表格、SEM 缺失处理、Promax EFA、二分类中介/调节中介或自动结果叙述：

1. 前端测试、类型检查和构建全部通过；
2. Promax、FIML、Logistic 和简单斜率图完成金标准验证；
3. 自动解释经过逐模板契约测试，且不再混淆简单斜率与条件间接效应；
4. CFA/lavaan 对照测试使用一致标度并在多数据集上稳定运行；
5. README 和界面准确披露支持边界。

满足这些门槛后，项目可以先定位为：**面向横截面、单层、连续变量 CB/OB 问卷研究的可复现实证工作台**。待实验、多层和纵向方法补齐后，再扩大“各类论文”的产品表述。
