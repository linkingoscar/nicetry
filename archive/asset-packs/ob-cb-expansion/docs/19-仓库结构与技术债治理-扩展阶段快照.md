# 仓库结构与技术债治理

> 更新日期：2026-07-18
> 文档角色：当前仓库定位规则与结构治理；实时债务状态以 `debt-register.json` 为准，OB/CB 产品与方法路线图以 `27` 为准，代码—业务—文档接线证据以 `28` 为准。

## 1. 当前结构

项目采用本地优先的模块化单体。HTTP 入口仅组合依赖与路由；统计实现、持久化、导出与 UI 展示按可调用边界分离。

```text
apps/api/app/
  main.py                       # FastAPI 应用工厂
  api/routes/                   # system/datasets/models/analyses/advanced
  services/
    dataset_repository.py       # 仓储 facade 与数据集元数据
    *_repository.py             # 测量、模型、分析任务聚合
    empirical_analysis.py       # R 调用与结果落盘
    empirical_export.py         # Excel 论文表格导出
apps/web/src/
  api/                          # 分域客户端；contracts.ts 引用生成 DTO
  types/generated-api.ts        # OpenAPI 自动生成，禁止手改
  types/advanced.ts             # 高级分析聚焦类型；types.ts 仅兼容 barrel
  components/{advanced,empirical,results,shared,model-builder}/
engine/R/
  run_analysis.R               # PROCESS/path/SEM 入口
  run_empirical_analysis.R     # 问卷实证中心入口
  run_advanced_analysis.R      # 五个 experimental family 的受限切片入口
  worker.R                     # 常驻 R 任务宿主
  lib/                          # runtime、回归、bootstrap、EFA、CFA、效度、SEM
specs/                          # 跨语言领域 JSON Schema
project.manifest.json           # 机器可读入口和命令地图
```

## 2. 已偿还的技术债

| 领域 | 处理结果 |
|---|---|
| 巨型 FastAPI 入口 | 改为应用工厂、依赖容器和 5 个领域路由。 |
| 单体仓储与实证服务 | 仓储按测量/模型/任务拆为 mixin 聚合；Excel 导出从 R 执行服务分离，公共 API 保持兼容。 |
| 巨型 R 入口 | SEM、回归推断、bootstrap、EFA、CFA、效度和运行时函数进入 `engine/R/lib`；入口只保留分析流程编排。 |
| 巨型 React 文件 | 模板领域逻辑、碎石图、相关热图、简单斜率图和学术解读渲染均独立；兼容导出保留。 |
| 单体 M3 测试 | 共享数据/模型工厂独立，验证、执行、问卷实证与 Logistic 回归分别测试。 |
| 人工维护 HTTP 请求 DTO | 固定版本的 OpenAPI 生成 TypeScript；高级分析 spec 直接引用生成类型，各 API payload 以生成 DTO `satisfies` 校验。人工类型只承担结果展示 view model。 |
| 静态检查缺口 | Ruff 0.15.21、Biome 2.5.3、TypeScript、契约漂移、架构边界和 R 锁校验均进入总测试。 |
| R 依赖未锁定 | 提交 `renv.lock`，安装使用 `renv::restore()`，测试校验 7 个 R 包版本。 |
| 文件与入口不可发现 | 提供 manifest、仓库 AGENTS、分域 barrel、OpenAPI 和 R engine map。 |
| 一次性/重复实现残留 | 删除已完成的 CSS 迁移脚本、旧式测试数据清理器、重复数据集分析服务、零引用 API 包装和不可达 R 执行分支；清单与保留判据见 `28`。 |

## 3. 当前债务状态

本轮审计列出的结构性技术债和可证明零引用的源码残留已关闭；这不表示运行时性能债、治理债、迁移债、安全债、方法真实性债和发布债已经关闭。当前剩余项与代码接线状态见 `28` 和 `debt-register.json`。已确认的计算、状态、I/O 和前端渲染问题及实施顺序记录在[性能债审计与优化路线图](20-性能债审计与优化路线图.md)，跨领域债务与长期稳健开发验收条件记录在[长期可持续开发债务复审与治理基线](21-长期可持续开发债务复审与治理基线.md)。下面项目属于持续治理规则，不作为本轮结构拆分的遗留缺陷：

- 依赖升级按月分批；R/lavaan、NumPy 或统计算法升级必须运行金标准测试；
- 新增响应 DTO 时优先补 Pydantic `response_model`，让 OpenAPI 生成类型替代新的手写 wire type；
- 高级统计能力仍按 [开发指南与接口规范](18-高级统计方法开发指南与接口规范.md) 的阶段门实施。当前五个 family 均有 runner，因而 family 级 `executionAvailable=true`；未实现 slice 必须由 slice capability/验证错误明确拒绝，不能再依赖 family 级 false 隐藏。
- 研究生命周期、实验/问卷方法和论文证据链的目标架构见 `27`；未进入 Schema/代码的对象均为 planned。

## 4. 自动门禁

- 手写源码硬上限 800 行；生成的 `generated-api.ts` 单独豁免；
- service 与测试文件上限 500 行，R 入口和 React 组件上限 800 行；
- service 禁止反向依赖 HTTP 层；兼容入口保持薄文件；
- `npm run check:contracts` 必须证明 OpenAPI 与生成客户端无漂移；
- Ruff、Biome、TypeScript、Vitest、pytest、R lock 与架构检查全部通过才可合并。

## 5. 调用定位规则

1. 查公开 HTTP 能力：`/api/openapi.json`；
2. 查高级能力是否可执行：`/api/v1/advanced-analyses/capabilities`；
3. 查路径归属：`project.manifest.json`；
4. 查前端请求：`apps/web/src/api/<domain>.ts`，wire DTO 看 `api/contracts.ts`；
5. 查统计公式：`engine/R/lib` 与对应金标准测试；
6. 查领域持久化：`dataset_repository.py` facade 及三个 `*_repository.py` 聚合。

对高级方法还必须追加第 7 步：使用 validate 端点和 `18` 的 slice 矩阵核对具体设计；capabilities 当前只能证明 family runner 存在。

`GET /api/v1/demo` 与 `POST /api/v1/analyses/mediation` 是测试、运行时基准和最小诊断所需的兼容入口，不是当前前端主流程；前端只接入 `POST /api/v1/demo/load`。兼容入口必须保持薄层并在 `project.manifest.json`/`28` 登记，失去诊断、测试和基准消费者后才可删除。

## 6. 新增规范

- barrel 与应用入口不放业务逻辑；
- 新 API 同步 Pydantic、OpenAPI 生成结果、客户端 payload 校验和测试；
- 新统计模块提交 provenance、边界测试、独立数值对照和失败语义；
- 生成物、缓存、临时数据和本地状态不得进入源码目录；
- 接近门禁上限时按职责拆分，不以提高上限规避治理。
